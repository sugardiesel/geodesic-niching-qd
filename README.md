# Geodesic Niching in Learned Behavior Spaces

This repository contains a Quality-Diversity project testing whether graph-geodesic
distance improves niche assignment in a learned behavior space. Three methods are evaluated in a
custom continuous foraging environment: hand-crafted MAP-Elites, an AURORA-inspired Euclidean
learned-descriptor baseline, and geodesic niching over a k-nearest-neighbor graph. Across two maps,
the experiments find no detectable archive-level improvement from geodesic assignment.
The audit identifies a structural limitation: a sparse evolving point graph does not reliably
attach to the dense fixed archive grid, leaving many centroid niches permanently unreachable.

All environment, policy, autoencoder, archive, MAP-Elites, graph, and analysis code was written
for this project. No public QD implementation was imported or adapted.

## Repository layout

- `envs/`: `ForageMaze2D` and the corner-safe maze shortest-path solver.
- `algorithms/`: policy, mutation, MAP-Elites, autoencoder, archive metrics, and geodesic graph.
- `configs/`: environment, baseline, contribution, smoke-test, and production protocols.
- `scripts/`: experiment entry points, production sweeps, diagnostics, and post-hoc analyses.
- `analysis/`: reusable scientific plotting code.
- `tests/`: unit, integration, connectivity-fallback, and synthetic ground-truth tests.
- `results/`: completed runs, diagnostics, tables, and figures.
- `results/final_summary/`: final tables, figures, and provenance.

The compiled exam report is submitted separately and is not included in this code repository.

## Requirements

- Python 3.11 or 3.12
- [`uv`](https://docs.astral.sh/uv/)
- NVIDIA GPU recommended for autoencoder training; CPU execution is supported but slower

Dependencies are fixed by `pyproject.toml` and `uv.lock`. PyTorch uses the official CUDA 12.8
wheel index. No external dataset or pretrained checkpoint is required: trajectories and training
data are generated by the custom environment.

## Installation

From the repository root:

```powershell
uv sync --frozen --extra dev
uv run pytest -q
uv run ruff check .
```

The first command creates `.venv` and installs the exact locked environment. The test suite is
fast and does not run the 20,000-evaluation production searches.

## Quick check

Run the environment and maze-distance validation into an ignored scratch directory:

```powershell
uv run python scripts/run_phase1_validation.py `
  --config configs/phase1_horseshoe.yaml `
  --output-dir reproduced/phase1_validation
```

Run the geodesic smoke test:

```powershell
uv run python scripts/run_phase4_geodesic_niching.py `
  --config configs/phase4_geodesic_niching_smoke.yaml
```

The smoke configuration uses only 300 evaluations and writes to `reproduced/phase4_smoke/`.

## Run the production experiments

The production protocol uses the same seeds across all three methods, 20,000 evaluations per
run, and `k=20` for geodesic assignment and reporting. The commands below launch new searches in
the ignored `reproduced/` directory so the committed evidence remains unchanged.

Horseshoe map, five seeds per condition:

```powershell
uv run python scripts/run_phase5_sweep.py `
  --protocol configs/production_protocol.yaml `
  --output-dir reproduced/phase5_horseshoe `
  --food-respawn-timing historical `
  --no-resume
```

Open-map robustness check, three seeds per condition:

```powershell
uv run python scripts/run_phase5_sweep.py `
  --protocol configs/phase6_open_robustness_protocol.yaml `
  --output-dir reproduced/phase6_open `
  --food-respawn-timing historical `
  --no-resume
```

These are the expensive commands: together they launch 24 searches and can take several
hours. The committed `results/phase5/` and `results/phase6_open_robustness/` directories contain
the completed runs used for the final analysis.

The explicit `--food-respawn-timing historical` option uses the original timer rule for
reproducing saved experiments. Without an option, the simulator retains the corrected rule,
which respawns food one step later. The sweep records the selection in generated configs and
run summaries and refuses to resume results with different or unrecorded timing. No maps,
fitness weights, search budgets, or graph parameters change with this option.

The compatibility option was checked against saved Baseline B and Contribution policies;
no new production sweep was run to validate it. Commands for these bounded checks and their
results are in `results/submission_verification/README.md`.

Individual methods can also be run directly:

```powershell
uv run python scripts/run_phase2_map_elites.py --config configs/phase2_handcrafted_map_elites.yaml --food-respawn-timing historical
uv run python scripts/run_phase3_aurora_euclidean.py --config configs/phase3_aurora_euclidean.yaml --food-respawn-timing historical
uv run python scripts/run_phase4_geodesic_niching.py --config configs/phase4_geodesic_niching.yaml --food-respawn-timing historical
```

Baseline B and the Contribution share the architecture and retraining schedule but train
independent encoders on their own collected trajectories. Their comparison is therefore an
end-to-end algorithm comparison rather than a fixed-representation metric ablation.

## Rebuild the analysis

Rebuild the summary tables and most figures from the committed production runs:

```powershell
uv run python scripts/prepare_report_inputs.py
```

Recompute the rolling-only k-sensitivity table and both figure layouts:

```powershell
uv run python scripts/audit_rolling_only_k_sensitivity.py
uv run python analysis/report_k_sensitivity_figure.py --layout vertical
uv run python analysis/report_k_sensitivity_figure.py --layout horizontal
```

Additional post-hoc analyses, all using completed searches rather than launching evolution:

```powershell
uv run python scripts/analyze_phase5_geodesic_disagreement.py `
  --phase5-dir results/phase5/contribution_geodesic_niching `
  --output-dir reproduced/disagreement_horseshoe
uv run python scripts/analyze_phase5_geodesic_disagreement.py `
  --phase5-dir results/phase6_open_robustness/contribution_geodesic_niching `
  --output-dir reproduced/disagreement_open
uv run python scripts/analyze_common_behavior_space.py
uv run python scripts/audit_geodesic_connectivity_penalty.py
uv run python scripts/audit_elite_support_connectivity.py
```

The connectivity audits are post-hoc replays and do not rerun MAP-Elites. See the script help and
the README files in their result directories for the longer per-seed diagnostic commands.

The original Baseline B sample NPZs and final encoder checkpoints are included. The samples are
required by the static elite-retention audit. Common-space analysis uses the saved final encoder
coordinates and recorded archive insertions to recover elite identities. To regenerate the small
Baseline B identity-verification CSVs from the checkpoints:

```powershell
uv run python scripts/recover_baseline_elite_latents.py
uv run python scripts/analyze_common_behavior_space.py
```

This replays only ambiguous historical policies. It does not run a new search or train an encoder.
The compatibility environment retains the original food-respawn timing and rejects a replay
if its logged fitness, episode counters, or trajectory features do not match.

## Final configuration

The final Contribution uses the rolling-buffer implementation at `k=20`:

- fixed `25 x 25` archive grid;
- most recent 1,000 real visited latent codes as routing support;
- graph refresh every 250 evaluations;
- centroids are assignment endpoints only;
- no centroid-to-centroid edges and no centroid transit;
- finite scale-derived fallback for disconnected distances;
- archive-elite retention disabled in production.

The elite-retention support variant was evaluated post hoc and is not used in production.

Exact replay showed that an average `222.8/625` horseshoe centroids and
`204.3/625` open-map centroids were never reachable at any post-retraining graph refresh. The
finite penalty was never the winning assignment route, so the observed starvation is an endpoint
support limitation rather than a penalty-selection artifact.

## Metrics

- Shifted QD-score: `sum(max(raw_fitness - (-5.0), 0))` over occupied archive cells.
- Raw QD-score is logged separately.
- Occupancy entropy is `log(filled_cells) / log(total_cells)` and is coverage-derived.
- Pairwise spread is reported with Euclidean and `k=20` graph-geodesic descriptor distance.
- Shared-seed comparisons use two-sided paired Wilcoxon signed-rank tests.
- The representation-independent `8 x 8 x 8` grid uses path efficiency, loop score, and food
  collected.

Detailed numbers and figure provenance are listed in `results/final_summary/README.md`.
